## 1. Executive Summary

This report documents the systematic forensic verification, remediation, and stabilization executed during Phase 1 for the Bubakan Green platform. The mandate of this phase is strictly confined to internal testing stability, empirical problem remediation, and codebase correctness across six core operational axes:

1. **Stability & Build Integrity:** Deterministic compilation of internal debug APK (`assembleDebug`) and complete test suite execution (`testDebugUnitTest`).
2. **Physical Installation Diagnostics:** Explicit scientific separation between Android Package Parsing failures (`INSTALL_PARSE_FAILED_NOT_APK`) and Google Play Protect / Unknown Sources developer warnings.
3. **Firebase Authentication Provider:** Root cause identification of disabled Email/Password authentication in Firebase Console and end-to-end admin credential verification flows.
4. **Admin Authorization & Security Model:** Enforced role-based access control against `/users/{uid}` with immutable Firestore Security Rules rejecting unauthenticated and unauthorized writes.
5. **Canonical QR Contract & Deep Links:** Absolute elimination of domain typos (`bubakangreen.web.app` -> `bubakan-green.web.app`) across all codebases, manifests, generator scripts, and unit tests.
6. **Default Plant Quiz Fallback:** Autonomous fallback to the verified 135-question repository (`DefaultLearningData.kt`) when remote Firestore collections are unpopulated, with defensive null-state handling for custom plants.

## 3. Physical Installation Root Cause Classification

Physical device testing revealed two distinct installation barriers that must never be conflated:

### Barrier A: Package Parsing Failure (`INSTALL_PARSE_FAILED_NOT_APK`)
- **Reported Error:** *"Ada masalah saat mengurai paket"* / *"Package appears to be invalid"*.
- **Root Cause:** Due to a Firebase Hosting SPA catch-all rule (`** -> /index.html`) on the Spark plan, requests to `https://bubakan-green.web.app/downloads/bubakan-green.apk` were serving the 52 KB `index.html` file with `application/vnd.android.package-archive` MIME type because binary APKs were excluded from hosting deployment. When Android's native `PackageParser` evaluated the HTML document, it halted with `INSTALL_PARSE_FAILED_NOT_APK`.
- **Classification:** `G. CORRUPTED DOWNLOAD PIPELINE` (Web server misconfiguration).
- **Remediation:** Internal testing uses local ADB installation or direct binary transfer of the genuine 30.2 MB APK (`app-debug.apk`), which parses with 100% validity.

### Barrier B: Google Play Protect & Android Security Gate
- **Reported Error:** *"Aplikasi diblokir untuk melindungi perangkat Anda ... Play Protect belum pernah melihat aplikasi dari developer ini sebelumnya."* / *"Unknown sources restricted"*.
- **Root Cause:** The testing APK is built with `android:debuggable="true"` and signed with the open-source `CN=Android Debug` key. Android 14+ (API 34+) actively warns users when sideloading unrecognized debug packages outside of Google Play.
- **Classification:** `D. Play Protect warning/block` + `C. unknown-source restriction`.
- **Testing Remedy:** For QA and internal dogfooding, the user taps *"Detail selengkapnya"* -> *"Tetap instal"*.
- **Production Pre-condition:** A formal release keystore (`release.keystore`) with `isDebuggable = false` will be generated in Phase 2. Debug builds must NEVER be released to the public.
